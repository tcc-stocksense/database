Identidade de cada mercadinho cadastrado no sistema
multi-tenant

produto
Catálogo de itens + resultados persistidos do motor preditivo
central do sistema
  • 🔑
    id PK
    Identificador único do produto. Referenciado por todas as outras tabelas de movimento.
    INT
  • 🔗
    estabelecimento_id FK
    Liga o produto ao mercadinho dono dele. Isola o catálogo entre estabelecimentos diferentes.
    INT
  • 🏷️
    nome
    Nome do produto exibido na interface e nos alertas (ex: "Banana Prata kg").
    VARCHAR(100)
  • 🗂️
    categoria
    Agrupamento do produto (ex: "Hortifruti", "Laticínios"). Usado na curva ABC por categoria.
    VARCHAR(50)
  • 📐
    unidade_medida
    Define como a quantidade é contada: "kg", "un", "cx". Essencial para a escala das previsões.
    VARCHAR(10)
  • 💰
    preco_custo / preco_venda
    Base para calcular Custo das Mercadorias Vendidas (CMV) e impacto financeiro da ruptura no dashboard do gestor.
    DECIMAL(10,2)
  • 📊
    estoque_atual
    Quantidade em estoque agora. Comparado com ponto_reposicao para decidir se o alerta deve ser disparado.
    INT
  • 🅰️
    classe_abc
    Classificação automática: A (top 20% do faturamento), B (30%) ou C (50%). Desnormalizado por performance — atualizado pelo cron mensal.
    CHAR(1)
  • 📈
    desvio_padrao_demanda
    Volatilidade histórica da demanda (σ). Insumo direto da fórmula do estoque de segurança: Z × σ × √lead_time.
    DECIMAL(10,4)
  • 🎯
    nivel_servico_alvo
    Probabilidade alvo de não haver ruptura (padrão: 0.95 = 95%). Define o Z-score usado no cálculo do estoque de segurança.
    DECIMAL(5,2)
  • 🆕
    ponto_reposicao NEW
    Output central do motor: D̄ × Lead Time + Estoque de Segurança. Quando estoque_atual ≤ ponto_reposicao, o alerta é gerado. Persistido aqui para o frontend ler sem recalcular.
    INT
  • 🆕
    estoque_seguranca NEW
    Reserva mínima calculada para absorver variações inesperadas de demanda ou atraso do fornecedor. Componente do ponto de reposição.
    INT
  • 🆕
    data_ultimo_calculo NEW
    Timestamp do último recálculo pelo motor Python. Exibido na interface para o gestor saber se a previsão está atualizada.
    TIMESTAMP

venda
Série temporal de vendas — principal insumo do motor de IA
maior volume
  • 🔑
    id PK
    Identificador único de cada registro de venda (item a item, não por transação).
    INT
  • 🔗
    estabelecimento_id FK IDX
    Permite filtrar vendas por loja no dashboard. Faz parte do índice composto para performance do motor.
    INT
  • 🔗
    produto_id FK IDX
    Liga a venda ao produto vendido. Junto com estabelecimento_id e data_hora forma o índice principal do motor.
    INT
  • 📅
    data_hora IDX
    Carimbo de data e hora da venda. Base de toda a série temporal — o Python agrupa por DATE(data_hora) para calcular demanda diária.
    TIMESTAMP
  • 🔢
    quantidade
    Unidades vendidas neste registro. Somado por dia, forma a variável "y" que alimenta os modelos Holt-Winters e Prophet.
    INT
  • 🏷️
    is_promocional
    Flag que marca se a venda ocorreu em período promocional. Passada ao Prophet como regressor externo para isolar picos de promoção da sazonalidade real.
    BOOLEAN
  • 💵
    valor_venda
    Receita gerada por este registro. Base do cálculo de faturamento para a curva ABC e do indicador de impacto financeiro da ruptura.
    DECIMAL(10,2)
  • ❌
    venda_perdida_estimada
    Estimativa de receita perdida por ruptura (produto em falta quando havia demanda). Alimenta o KPI "Índice de Ruptura" no dashboard do gestor.
    DECIMAL(10,2)
🗑️
perda_estoque
Módulo ESG — rastreio de desperdício separado das vendas reais
ODS 12
  • 🔑
    id PK
    Identificador único de cada evento de perda registrado.
    INT
  • 🔗
    estabelecimento_id FK FIX
    FK declarada corretamente (estava sem constraint na versão anterior). Fixo em 1 no MVP, mas com integridade referencial garantida pelo banco.
    INT DEFAULT 1
  • 🔗
    produto_id FK IDX
    Qual produto foi perdido. Indexado junto com data_perda para o relatório ESG mensal.
    INT
  • 🔢
    quantidade
    Unidades descartadas. Somado por período para o KPI "Redução de Desperdício" e para cálculo do prejuízo financeiro (quantidade × preco_custo).
    INT
  • 📋
    motivo
    Causa da perda: "Vencimento" (alimenta o dashboard ESG), "Avaria" (danos físicos) ou "Furto" (quebra operacional). Segrega tipos distintos de perda para análise.
    VARCHAR(50)
  • 📅
    data_perda IDX
    Quando a perda foi registrada. Indexado para consultas de relatório ESG por período (mensal/trimestral).
    TIMESTAMP

Persiste resultados do motor Python — coração dos alertas
NEW · v2.1
  • 🔑
    id PK
    Identificador único de cada previsão gerada. Uma nova linha é inserida a cada execução do cron mensal por produto.

    Métricas de acurácia do modelo nesta execução. Armazenadas aqui para o dashboard técnico comparar Holt-Winters vs Prophet ao longo do tempo.

Índices de Performance

idx_venda_produto_data
ON venda(estabelecimento_id, produto_id, data_hora)
Cobre a query principal do motor de IA: filtra por loja + produto e ordena por data em uma única operação. Sem este índice, cada execução do Python faria um full-scan na maior tabela do sistema. A ordem dos campos (estabelecimento → produto → data) é intencional e otimizada para a query de série temporal.
idx_previsao_produto
ON previsao(estabelecimento_id, produto_id, data_previsao)
Cobre o endpoint GET /alertas do Spring Boot: busca todas as previsões de uma loja com dias_ate_ruptura abaixo de um limite. Sem este índice, o endpoint degradaria a cada novo produto cadastrado.
idx_perda_produto_data
ON perda_estoque(produto_id, data_perda)
Cobre o relatório ESG mensal: soma as perdas por produto em um período. O cron do Spring Boot executa este relatório uma vez ao mês — o índice garante que não impacte o desempenho geral do sistema.
